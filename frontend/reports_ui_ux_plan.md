# План улучшений UI/UX для страницы Reports

## Введение

На основе анализа backend API (reports.py) и модели данных InspectionResult, а также документации Ant Design v6.2.1, предлагается план улучшений пользовательского интерфейса страницы Reports. Цель - повысить usability, accessibility и эффективность работы с отчетами инспекций Kubernetes кластеров.

## Анализ текущего API

### Доступные эндпоинты:
- `GET /reports` - список отчетов с пагинацией
- `GET /reports/{report_id}` - детальный отчет
- `DELETE /reports/{report_id}` - удаление отчета
- `GET /reports/{report_id}/export/{format}` - экспорт (JSON, HTML, PDF)
- `POST /reports/immediate` - создание немедленного отчета

### Структура данных отчета:
- `result_id` - уникальный идентификатор
- `cluster_name` - имя кластера
- `inspection_type` - тип инспекции
- `timestamp` - время создания
- `total_items` - общее количество проверок
- `passed_count` - количество пройденных проверок
- `critical_count` - количество критических проблем
- `warning_count` - количество предупреждений
- `info_count` - количество информационных сообщений
- `result_data` - полные данные в формате JSON
- `execution_duration` - время выполнения
- `triggered_by` - инициатор (user/scheduler)
- `inspectors_used` - использованные инспекторы

## Предлагаемые улучшения UI/UX

### 1. Главная страница списка отчетов

#### Текущие проблемы:
- Отсутствие фильтров по ключевым параметрам
- Ограниченная сортировка
- Статическая пагинация

#### Предложения:

**Использование компонентов Ant Design:**
- `Table` с `columns` для отображения данных
- `Pagination` для навигации
- `Select` для фильтрации по inspection_type, triggered_by
- `DatePicker.RangePicker` для фильтрации по дате
- `Badge` для отображения severity уровней
- `Tag` для статуса и типов
- `Button.Group` для действий (просмотр, экспорт, удаление)

**Улучшения:**
- Сортировка по всем колонкам (timestamp DESC по умолчанию)
- Фильтры в боковой панели или в заголовке таблицы
- Статистика: общее количество отчетов, среднее время выполнения
- Быстрые действия: bulk delete, bulk export

### 2. Детальный просмотр отчета

#### Текущие проблемы:
- Сложная структура данных (inspection_results vs items)
- Отсутствие визуализации severity распределения
- Трудно найти конкретные проблемы

#### Предложения:

**Использование компонентов Ant Design:**
- `Card` для разделения секций отчета
- `Tabs` для разных типов инспекторов (popeye, node, etc.)
- `Table` с expandable rows для детального просмотра
- `Progress` или `Statistic` для отображения статистики
- `Alert` для критических проблем
- `Modal` для подробного просмотра solution/details
- `Collapse` для группировки по severity
- `Timeline` для последовательности проверок

**Улучшения:**
- Визуализация: pie chart для распределения severity (используя recharts)
- Фильтры внутри отчета: по severity, status, inspector type
- Экспорт отдельных секций
- **Блоки по severity:**
  - **Критические проблемы (Critical):**
    - Отображать в отдельном блоке с использованием `Alert` компонента для выделения критических проблем
    - Использовать красный цвет для визуального акцента
    - Показывать количество критических проблем и expandable список деталей
  - **Предупреждения (Warning):**
    - Отображать в отдельном блоке с оранжевым цветом
    - Использовать `Badge` или `Tag` для маркировки предупреждений
    - Группировать по типам инспекторов
  - **Информационные сообщения (Info):**
    - Отображать в отдельном блоке с синим цветом
    - Использовать `Collapse` для сворачивания/разворачивания
    - Показывать как менее приоритетные, но доступные для просмотра

### 3. Функциональность экспорта

#### Предложения:
- `Dropdown` с опциями экспорта (JSON, PDF, HTML)
- `Button` с иконкой download
- Progress indicator для больших экспортов
- Предварительный просмотр PDF/HTML в modal
- Не отображать кнопки экспорта для форматов, которые неактивны или недоступны для данного отчета, чтобы избежать путаницы пользователей.

### 4. Создание немедленных отчетов

#### Предложения:
- `Button` "Создать отчет" с loading state
- `Select` для выбора кластера
- `Modal` для конфигурации параметров инспекции
- Real-time progress с `Progress` компонентом

### 5. Общие улучшения UX

#### Доступность:
- Использование `aria-*` атрибутов
- Keyboard navigation
- Screen reader support

#### Производительность:
- Virtual scrolling для больших таблиц (`Table` с `virtual`)
- Lazy loading для детального просмотра
- Caching с react-query

#### Responsive design:
- `Grid` и `Col` для адаптивности
- Mobile-friendly таблицы с horizontal scroll

#### Темизация:
- Поддержка light/dark темы Ant Design
- Кастомные цвета для severity уровней

## Рекомендации по реализации

1. Использовать TypeScript interfaces для типизации данных отчетов
2. Реализовать custom hooks для API вызовов с react-query
3. Использовать zustand для глобального state (фильтры, настройки)
4. Добавить error boundaries для graceful error handling
5. Implement unit tests для компонентов с testing-library

## Метрики успеха

- Уменьшение времени на поиск конкретных проблем на 50%
- Увеличение скорости экспорта отчетов
- Положительная обратная связь от пользователей по usability
- Соответствие WCAG 2.1 AA стандартам доступности
